# Apex 1.32.0

The arrival redesign's engine: a Temporary Worker now links itself to a real Employee automatically once HR registers the matching passport (Batch 5).

## What changed for users

- **Automatic linking.** A daily task matches each active Temporary Worker's passport to an Employee carrying the same passport number. On a match it links them, re-points every housing and custody record from the Temporary Worker to the Employee, and marks the Temporary Worker Linked.
- **Cost catches up.** The accommodation cost skipped while the worker was on a passport (no Employee) is back-dated to the now-linked Employee, from his check-in date — so nothing is lost.
- **Lapsed windows are flagged.** A Temporary Worker whose window passes without a match is marked Expired and HR is notified in-app.

## What changed under the hood

- New daily scheduler `habitat/temporary_worker_link.link_temporary_workers`. Re-pointing is a direct, parameterised SQL update across the ten party doctypes (they include submitted documents — a system identity correction, not a user edit). Back-dating reuses the cost engine's per-day algorithm via a new idempotent `backdate_assignment_cost` (the existing daily allocator is untouched). HR notification uses a native Notification Log.
