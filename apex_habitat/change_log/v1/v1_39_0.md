# Apex 1.39.0

The daily accommodation cost allocation now runs on Frappe's background worker
queue, per building — so the scheduler is never blocked and large sites allocate
in parallel.

## What changed for users

- **Faster, non-blocking daily cost allocation.** The nightly accommodation cost
  allocation no longer runs as one long job on the scheduler; it now fans out one
  background job per building onto Frappe's "long" worker queue. The scheduler
  stays responsive and buildings are costed in parallel.
- **No change to the numbers.** The per-employee daily-share calculation and the
  ledger rows are identical; only *how* the work is dispatched changed. Re-runs
  remain idempotent (an existing ledger row for the day is never duplicated).

## What changed under the hood

- `daily_accommodation_cost_allocation` is now a thin dispatcher: it discovers the
  distinct buildings with active assignments and `frappe.enqueue`s the new
  `allocate_building_accommodation_cost(building, posting_date)` worker on the
  `long` queue (`enqueue_after_commit`, per-building `job_name`, 1h timeout).
- The worker holds the original capacity-denominator algorithm and existence
  guard, scoped to one building. Tests cover both the worker (end-to-end ledger +
  supplier markup) and the dispatcher (one enqueue per building on the long queue).

## If you are updating an existing site

- Run `bench migrate`, then `bench build` and `bench clear-cache`. Ensure a worker
  is processing the `long` queue (`bench worker` / your process manager).
