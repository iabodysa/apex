# Apex 1.31.0

Custody records can now hold a worker who arrived before being registered — the custody half of the arrival redesign (Batch 3), matching the housing records shipped in 1.30.0.

## What changed for users

- **Issue, return and assess custody for a pre-Iqama worker.** Custody Issue, Custody Return and Custody Damage Assessment now each carry a **Worker Type** (Employee or Temporary Worker) and a **Worker** field, so custody can be tracked for a passport-only Temporary Worker, not just a permanent Employee.
- **Nothing you rely on changes.** Each record keeps its existing Employee link (Issued To / Returned By / Employee Responsible), now filled in automatically from the Worker, so existing lists and reports keep working.
- **Consistent with housing.** This mirrors exactly what 1.30.0 did for the accommodation records, using the same native party-type / party link.

## What changed under the hood

- Added `party_type` (Select: Employee | Temporary Worker) + `party` (Dynamic Link) to Custody Issue, Custody Return and Custody Damage Assessment. Each doctype's Employee link (`issued_to_employee` / `returned_by_employee` / `employee`) is now a read-only mirror, kept in step by the shared `sync_party_employee` helper, which gained an `employee_field` parameter to handle the differing link names.
- Idempotent, existence-guarded, post-model-sync backfill (`patches/v1_x/backfill_custody_party`) stamps `party_type=Employee`, `party=<employee>` on existing rows.
