# Apex 1.45.0

Test isolation & coverage from the KB-grounded audit (Phase 3, tests).

## What changed for users

- No user-facing behavior change. This release hardens the automated test suite
  so future regressions in fleet/movement transitions are caught and so tests no
  longer leave stray data behind.

## What changed under the hood

- M-18 `test_salis_state_flow`: switched `TestDispatchTripStateFlow` from
  `unittest.TestCase` to `FrappeTestCase`, so its DB insert runs inside the
  per-test rollback guard (a regressing assertion no longer pollutes the test DB).
- M-19 `test_habitat_role_alignment`: removed the mid-test `frappe.db.commit()` in
  `test_reseeding_creates_no_duplicates_and_does_not_raise`; idempotency is now
  proven within the same uncommitted transaction, restoring the rollback safety net.
- M-20 new `test_submittable_controllers.py` (FrappeTestCase): adds coverage for
  the four previously-untested submittable controllers — Vehicle Handover, Vehicle
  Damage Write-Off, Movement Cost Transfer, Vehicle Stop. Each test exercises a
  validate/before_submit guard rejection plus one valid path (and, where observable,
  asserts the on_submit vehicle-mirror / status side-effect).

## If you are updating an existing site

- No migration needed; run `bench run-tests --app apex_habitat` to exercise the
  new coverage.
