# Apex 1.28.2

The operational notifications now deploy the framework-native way.

## What changed for users

- **Same notifications, native delivery.** The 16 operational notifications
  (license/lease expiry, maintenance, resident requests, safety incident, fleet
  compliance, overdue fuel, etc.) are unchanged and still ship disabled-by-default
  — but they now install as native standard records on `bench migrate`.
- **Nothing to do.** No behaviour change; enable the ones you want as before.

## What changed under the hood

- Converted the 16 Python-seeded Notifications into native `is_standard` JSON
  files under `<module>/notification/<name>/`, which Frappe auto-imports on migrate
  (Notification is in Frappe's importable set). Removed the two `notifications_seed`
  modules, five seed patches, and their hook/setup wiring; the release-hygiene test
  now harvests recipient roles from the JSON.
- Rule learned and recorded: ship a component as standard on-disk JSON only when
  its DocType is in Frappe's `IMPORTABLE_DOCTYPES` (Notification, Report, Print
  Format, Web Form, Workspace, …); the rest (Workflow, Kanban Board, Assignment
  Rule, Email Template, Dashboard/Chart/Card) genuinely require a seed.

## If you are updating an existing site

- Run `bench migrate`.
