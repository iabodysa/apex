# Apex Habitat 1.52

Apex 1.52.0 — Accommodation Building runs on its native sources (Address, Supplier, Lease), plus quick activate/deactivate for rooms and beds and faster access to the Room Setup wizard.

## 1.52.9

_Correctness pass — flagged-logic triage plus a deep adversarially-verified audit._

- Facility Asset Movement now actually moves the asset (it was a silent no-op writing non-existent fields); Rental Accrual rows are reconciled and stamped by their Settlement instead of staying "Unsettled" forever; Fuel Consumption Ledger entries can now be reversed.
- Several submittable documents that could never be cancelled — the required cancellation reason was locked — are now fillable; negative amounts on payment, cost-transfer, and claim records are rejected.
- Resident Requests convert into the right document (Maintenance / Safety / Custody) with a back-link; Work Orders carry their issue type so the material-template button works; the SLA-breach banner now computes correctly.
- Removed dead fields, corrected metadata that promised unbuilt behaviour, and added missing permission and amount guards across the app.

## 1.52.8

_App-wide form and workspace UX overhaul._

- Every DocType form is regrouped by concern: related fields sit together, audit and system fields move to their own tab or a collapsed section, and columns pack by field width.
- Workspaces overhauled — dashboard charts and live quick-lists wired in, report links given dedicated sections, shortcut tiles now show live counts, and every DocType is reachable from a workspace.
- Building room and floor counts now compute correctly (they were stuck at zero) and are backfilled on existing buildings; city and district auto-fill from the site.
- Hundreds of Arabic section labels added; toolbar buttons with two or fewer actions now show directly instead of under a menu.

## 1.52.7

_Form-layout polish across 27 DocTypes._

- Removed 25 single-purpose tabs across 27 DocTypes (lone child tables and 1-2 audit fields).
- Child tables now sit full-width in their Overview tab; system fields moved to a collapsed section.
- No tab now holds fewer than three fields; no field was changed, only repositioned.

## 1.52.6

_Reliability and hygiene cleanup._

- Scheduler jobs read their settings once per batch instead of per row.
- Cost-allocation ledger now ignores duplicate-key races quietly.
- Building per-capacity cost zeroes when capacity is removed.
- Removed a dead Salis helper and annotated a post-submit insert.

## 1.52.5

_Apex 1.52.5 — dashboards now provision the native Frappe way (is_standard module JSON, like ERPNext) instead of Python seeders._

- The 11 app dashboards (Habitat + Salis) now ship as native is_standard module JSON files — the same mechanism ERPNext uses for its own dashboards — auto-synced on install and migrate, instead of being hand-built by three Python seeders at runtime.
- Removed the double-provisioning where the Salis seeders re-created Dashboard Charts and Number Cards that already ship as module JSON (and flipped them to non-standard on every run).
- The three dashboard seeders are retired to documented no-op stubs; a one-time patch drops the old non-standard Dashboard records so migrate re-imports them natively.
- No dashboard was lost — every chart and number card was shipped as is_standard JSON, including the recovered Salis Finance Manager and Movement Operations dashboards; the workspace-linked Movement Operations dashboard resolves correctly.

## 1.52.4

_Apex 1.52.4 — security hardening on three endpoints, native-first cleanups, a floor-numbering guard, and the Arabic translation backlog cleared._

- Security: closed a catalog leak on the custody kiosk (the full Custody Article list was readable without a permission check), and gated the Temporary Worker passport/iqama PII and the Masar token secret on the arrival slip, plus the Maintenance Request read on Work Order creation, behind explicit permission checks.
- Security: the temporary-worker party-repoint UPDATE now validates its table and column identifiers against an allowlist pattern before building the SQL.
- Native-first: replaced three hand-rolled "users holding role X" queries with `frappe.utils.user.get_users_with_role`; replaced manual ToDo creation in the idle-resident report with the native `frappe.desk.form.assign_to.add` (so the desk Assigned-To panel and assignee notifications work); the supplier cost-recovery report now defaults its month/year from the server date instead of the browser clock.
- Bug fix: the room generator now rejects two floor-plan rows that resolve to the same floor code — previously a Ground floor and a Middle floor both at number 0 collided and silently dropped one floor's rooms.
- Arabic: cleared the translation backlog (35 strings translated, format placeholders preserved).

## 1.52.3

_Apex 1.52.3 — one consistent, neutral form layout applied across 13 DocTypes (the same structure as the Accommodation Building form), plus two form bug-fixes._

- Habitat and Salis forms now follow a single layout convention: named tabs (Overview / Related / System Info), sections with meaningful labels, editable inputs on the left with computed/read-only values on the right, tables in their own tab, and system/audit fields tucked into a System Info tab.
- Bug fix — a hidden field is now visible: Accommodation Assignment's check-in photo (room_condition_snapshot) was defined but absent from the form layout, so it never rendered; it now appears in the Overview tab.
- Bug fix — Accommodation Resident Request had no explicit field order at all; it now has a proper Overview + System Info structure.
- Restructured DocTypes: Accommodation Resident Request, Assignment, Maintenance Request, Custody Issue, Lease, Room and Bed; Transport Request, Dispatch Trip, Route Plan, Salis Driver, Salis Vehicle and Fuel Request. No field was added, removed, or renamed anywhere — fields were only repositioned and grouped.
- Arabic translations added for the new section and tab labels.

## 1.52.2

_Apex 1.52.2 — a migrate-stability fix, the Accommodation Site native address, an email master switch, and the Arabic translation backlog cleared._

- Migrate no longer fails with a "document is currently locked" error: the Role Profile was being re-imported as a fixture on every migrate, which left a stale lock whenever no background worker was running. Role Profiles now install only through their idempotent seeder (all seven still ship on fresh and existing sites); the redundant fixture file was removed.
- Accommodation Site now uses Frappe's native Address record (the same widget as the building), with a one-time, idempotent backfill that creates an Address from each site's existing city/district.
- New "Enable Email Notifications" master switch in Habitat Settings, OFF by default — a single kill-switch so the app sends no outgoing email until the site's mail is configured and the switch is turned on; the lone direct email send (the finance cost-center memo) now honors it.
- Arabic translations: the missing-translation backlog was cleared, with format placeholders preserved.

## 1.52.1

_Stability and clarity improvements across accommodation._

- A worker can no longer be placed in two beds at once, and the housing picker now lists only workers who still need a bed — so assignments and transfers stay consistent.
- The building screen is tidier: capacity and occupancy sit together, the internal room-plan table is tucked behind the Room Setup wizard, and a room or bed can only be taken out of service when no one is housed in it.
- More on-screen labels now read correctly in Arabic. Existing records are unchanged.

## 1.52.0

_Apex 1.52.0 — Accommodation Building runs on its native sources (Address, Supplier, Lease), plus quick activate/deactivate for rooms and beds and faster access to the Room Setup wizard._

- Building address now reads from Frappe's native Address record everywhere it is shown (the arrivals check-in slip and the worker portal), and the old free-text address field has been retired — one address, no duplicate copy to keep in sync.
- The landlord is now a Supplier link instead of free-text name/mobile/office fields, and is auto-filled from the building's active lease when set there.
- Annual rent is derived from the active Accommodation Lease (annualized by its billing cycle and the company's share) instead of being typed on the building; cost recovery always reads the current lease figure, so the two can no longer drift.
- Rooms and beds can be taken in or out of service from a single Activate / Deactivate button on their form — backed by the existing readiness/status the assignment and transfer checks already honor — and an occupied bed cannot be deactivated until its resident is checked out.
- A clear "Edit Rooms & Beds" button now sits beside the read-only Floor Plan table, opening the Room Setup wizard for that building so room and bed counts can be changed without hunting the toolbar.
