# Apex 1.35.0

A Unified Action Inbox — one screen showing each user only the documents that await their action, with inline Approve/Reject, mirroring the focused inbox of enterprise systems without leaving Frappe's native rails.

## What changed for users

- **One inbox for everything awaiting you.** A new "Action Inbox" page (under Apex Core) gathers, per user, only the documents that need your action — the workflow approvals you can act on, plus the tasks assigned to you — instead of hunting across separate lists. Anything already approved, already moved on, or done never shows up.
- **Approve or reject in place.** Each approval shows its real available actions; act on them inline, right from the inbox, without opening the document. The server re-checks your authority every time (including self-approval rules).
- **Always current.** The inbox refreshes itself, and a nightly cleanup removes stale approval rows left behind when a document was changed or deleted outside the normal flow — so the list stays honest.

## What changed under the hood

- Native-first, with NO new DocType. `get_pending_actions` unions the native Workflow Action source (auto-scoped by Frappe's own permission hook to the user's roles + status Open) and the user's open ToDos, behind a staleness guard that drops any Open action whose document has moved on. Inline actions go through the canonical `frappe.model.workflow.get_transitions` / `apply_workflow` (no new write path; the server re-validates). A daily `workflow_utils.cleanup_orphaned_workflow_actions` prunes orphaned Open rows (deletes only Open — Completed is the audit trail). The desk Page lives in Apex Core and is wired into its workspace.
