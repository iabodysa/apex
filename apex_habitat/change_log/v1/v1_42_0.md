# Apex 1.42.0

Permission & endpoint hardening from the KB-grounded audit (Phase 2, part 2).

## What changed for users

- **Drivers see only their own Trip Start Logs again.** A duplicate, unscoped
  permission row let any Driver list every project's Trip Start Logs while at the
  same time blocking them from opening their own. Drivers now correctly read the
  logs they created, and supervisors stay confined to their permitted projects.
- **Action endpoints now enforce record-level permissions.** Eight transition
  buttons (start/complete a task, start/miss a service order, start/complete a
  work order, generate rooms/safety setup, regenerate a lease schedule, load a
  material template) now check permission on the specific record, so a blanket
  write role can no longer drive these transitions on records the user should not
  reach.

## What changed under the hood

- M-4 Trip Start Log: removed the duplicate plain `{read, Driver}` DocPerm that
  defeated the `if_owner` scope. `trip_start_log_query` now ORs in `owner = me`
  (mirrors `salis_driver_query`), and a new owner-aware `trip_start_log_has_permission`
  hook replaces `scoped_has_permission` for the DocType (mirrors
  `salis_driver_has_permission`) so a project-tagged log the Driver owns is never
  blocked. DocPerm + query + has_permission now agree on own-only scope. Added
  two scoping tests to `test_salis_fleet_scope.py`.
- M-9: eight whitelisted action endpoints now load the document first and call
  `frappe.has_permission(dt, "write", doc=<doc>, throw=True)` so `if_owner`,
  User Permissions, and controller `has_permission` hooks run (a bare DocType-level
  check skipped all of them). Affected: `subcontractor_service_order` (start_work,
  mark_missed), `scheduled_task_instance` (start_task, mark_completed),
  `maintenance_work_order` (start_work, mark_completed), `accommodation_building`
  (generate_rooms_and_beds, generate_safety_setup), `accommodation_lease`
  (regenerate_schedule), `maintenance_material_template` (load_template_into_doc).

## If you are updating an existing site

- Run `bench migrate`, then `bench build` and `bench clear-cache`.
