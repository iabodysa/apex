# Apex 1.38.0

A role and permission alignment pass: four new least-privilege Habitat roles,
matching Role Profiles, universal-but-private Maintenance Request intake, and
read-only oversight for the Internal Auditor.

## What changed for users

- **Anyone can raise a Maintenance Request — and only sees their own.** Every
  signed-in user can now report a maintenance issue without holding a special
  role. A raiser sees only the tickets they opened; no one can browse another
  person's tickets. The technician a ticket is assigned to sees it too (assignee
  list visibility applies to operational role holders such as Maintenance
  Technician). Oversight roles (Accommodation Manager, Resident Supervisor,
  Resident Request Coordinator, System Manager) still see and act on every ticket.
- **Four new operational roles.** Maintenance Technician, Cleaning Supervisor,
  Safety Officer, and Resident Request Coordinator give front-line staff exactly
  the access they need — and nothing more.
- **One-click role bundles.** New Role Profiles (Habitat Maintenance Technician,
  Habitat Cleaning Supervisor, Habitat Safety Officer, Habitat Resident Request
  Coordinator) let an administrator grant a complete operational profile in a
  single step.
- **Internal Auditor can review everything, change nothing.** The Internal
  Auditor now has read and report access across the custody, asset, movement,
  and ledger records, with no write, create, submit, or delete rights anywhere.
- **Procurement and inventory use the native ERPNext roles.** No bespoke roles
  were invented where Stock and Purchase roles already fit.

## What changed under the hood

- New `habitat/permissions.py`: `maintenance_request_query` (owner/assigned
  scoping in list and report views) and `maintenance_request_has_permission`
  (the same boundary on form, REST, and link reads), wired in `hooks.py` and
  mirroring the Salis scoped-permission pattern. The Maintenance Request
  controller stamps `reported_by` server-side so ownership cannot be spoofed.
- `setup.py` seeders `create_roles` / `create_role_profiles` extended for the
  four new roles and profiles — create-only and existence-guarded, and wired into
  both `after_install` and `after_migrate` so upgrading sites receive them (Role
  Profiles are not fixtured); idempotent across repeated `bench migrate` runs.
- DocPerm rows added to the custody / asset / movement / ledger DocTypes for the
  Internal Auditor (read + report only) and to the relevant intake DocTypes for
  the new operational roles — applied in each DocType's source JSON and brought
  in by the standard DocType sync on migrate.
- The four new roles ship as a complementary `Role` fixture entry that never
  clobbers an ERPNext- or HRMS-owned role.

## If you are updating an existing site

- Run `bench migrate`, then `bench build` and `bench clear-cache`.
