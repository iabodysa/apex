# Apex 1.36.0

A data-driven seed loader — the app's default records (email templates, task
boards, assignment rules and maintenance catalogs) now load from plain JSON
data files through one shared, create-only loader, instead of a dozen separate
hand-written seed scripts. Records you have tuned are never overwritten.

## What changed for users

- **Your edits to default records are protected.** The loader is *create-only*:
  it adds a default record only if it is missing, and never overwrites one you
  have changed (verified against a live site — an edited template kept your edit
  while a deleted one was restored).
- **Default records stay in sync on every update.** Email Templates, Assignment
  Rules, Kanban Boards and the Maintenance material/template catalog are
  re-asserted on every `bench migrate`, so a newly added default reaches existing
  sites without manual steps — and a default someone deleted is restored.
- **No duplicates.** Re-running the loader on an already-seeded site creates
  nothing new and changes nothing.

## What changed under the hood

- New loader `apex_habitat/tools/setup/seed.py` reads
  `tools/setup/data/<module>/<doctype>.json` and upserts create-only, guarded on
  the DocType and every Link target, each record in its own savepoint
  (log-then-rollback) so one bad record never aborts the batch. Wired into
  `after_install` and `after_migrate`.
- Eight record sets were externalised to JSON with byte-for-byte parity tests
  against the legacy seeders (Habitat + Salis Email Templates, Assignment Rules,
  Kanban Boards, plus Habitat maintenance materials/templates). Records whose
  fields are resolved at runtime (Auto Email Report's recipient/report type, an
  SLA's holiday list) deliberately stay on their existing seeders.
- The legacy `*_seed.py` modules still run alongside the loader (both
  create-only) and will be retired in a later, gated cleanup.

## If you are updating an existing site

- Run `bench migrate`, then `bench build` and `bench clear-cache`.
