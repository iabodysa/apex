# Apex Habitat 1.54

Six business features: financial integration, salary-deduction layer, cost-field privacy, safety auto-tickets, rider guard, and model cleanup.

## 1.54.30

_Custody value-at-risk surfaced on the Custody workspace_

- New 'Custody Value in Employee Hands (SAR)' card showing SAR still held by workers
- New 'Damage Cost by Building' chart and 'Custody Outstanding by Worker' report
- Custody workspace reorganized: key metrics first, kiosk shortcut, returns-to-reconcile queue

## 1.54.29

_A smarter, faster Safety Checklist — it shows only what's due and emails the manager._

- The Safety Checklist now shows only the rounds that are due right now — daily, weekly, monthly and so on appear automatically from what was last done, so the supervisor never picks a cadence by hand.
- Each task is checked with one tap (pass, fail, or issue) plus an optional note, and the whole visit is submitted in one step on a new mobile-friendly screen at /safety.
- When a round is submitted, a report is emailed to the manager — the recipient is configurable in Habitat Settings, otherwise it goes to the Accommodation Manager.

## 1.54.28

_The Safety Checklist page — run a building's safety round in one screen._

- New Safety Checklist page: pick a building and a cadence, tick off that cadence's safety tasks, and submit the whole round in one step — it records the round and each task result together and shows the overall result.
- The page is open to the supervisor roles that can sign off a round (Accommodation Manager, Resident Supervisor, System Manager) and is linked from the Safety workspace.
- The old Safety Inspection Report is now fully retired from the desk: its number card and trend chart read the new Safety Rounds, and the safety onboarding step opens the new page.

## 1.54.27

_Safety Rounds for building safety checks, plus a cleaner Fleet board._

- New Safety Round: group a building's safety-task checks for one cadence (daily, weekly, monthly, and so on) into one submittable round that derives a Pass, Needs Attention, or Fail result.
- New Safety Round Compliance report shows, per task, the latest status and what still needs attention for a chosen building and period.
- The old Safety Inspection Report is retired in place (hidden and read-only); existing records are kept and new work uses Safety Rounds.
- The Fleet dashboard now uses a clean professional Lucide icon set instead of emoji.

## 1.54.26

_Buildings now show their saved address automatically._

- Accommodation Buildings that had an address recorded before the dedicated Building Address field now display it on the form automatically, instead of falling back to the site's address.
- The fill-in runs once on update and never overwrites a building that already has a Building Address set.
- Buildings with no recorded address are left unchanged.

## 1.54.25

_A building's supervisor field now drives that supervisor's building access._

- Setting the Responsible Facility Supervisor on an Accommodation Building automatically grants that user the building-scoped User Permission.
- Changing the supervisor moves the access to the new person and removes it from the previous one; clearing the field removes it.
- Building access now follows the supervisor field as the single source of truth, instead of maintaining a separate permission by hand.

## 1.54.24

_The Accommodation Building form can now carry its own address._

- A new Building Address field lets you select an Address for the building itself.
- When it is set, the building shows its own address; when empty, it falls back to the Accommodation Site's address as before.
- The shown address updates immediately when you pick or change it — no save-and-reload needed.

## 1.54.23

_The Accommodation Building form's Site address display is now correct._

- Switching the Site dropdown now immediately shows the chosen site's address, instead of keeping the previously-saved site's address until you saved and reloaded.
- The address lookup reads the site you picked in the form rather than the one stored on the record.
- The lookup is permission-checked on the chosen site, so it cannot be used to read an unrelated site's address.

## 1.54.22

_The driver portal's trip cards are now readable._

- Each trip card shows the vehicle's plate number instead of its internal record id.
- It shows the route's name instead of the internal route-plan id.
- If a label is ever missing the card falls back to the id rather than showing nothing.

## 1.54.21

_Housing requests from workers with no active accommodation assignment are now flagged cleanly._

- When a worker raises a request while they have no active accommodation assignment, it now carries a structured "No Active Assignment" flag instead of an English note pasted into the description.
- That note used to follow the session language rather than the worker's, so an Arabic worker saw English in their own request; the Arabic request screen no longer leaks English here.
- Supervisors can now filter and triage these orphaned-context requests by the flag instead of scanning the description text.

## 1.54.20

_More Habitat desk screens now render fully in Arabic._

- The arrivals-desk action buttons and counters (arrived this session, create / print / issue all, QR created) now show in Arabic instead of English.
- The room-setup floor summary line and the maintenance "materials loaded from template" message are now translated.
- The Arabic-coverage guard test was widened from the fleet pages to the whole app's desk and www surfaces, so any new untranslated screen string fails the build.

## 1.54.19

_The Fleet Control page and several fleet and housing surfaces now render fully in Arabic._

- The Fleet Control page no longer shows its export-count and open-incident labels in English — they are now translated like the rest of the board.
- 55 status, alert and action strings across the fleet and housing desk pages, the fuel console and settlement messages were added to the Arabic translations.
- A coverage test now fails the build if any fleet desk page or the `/fleet` portal adds a translate-call string without an Arabic entry, so new surfaces can't ship untranslated.

## 1.54.18

_Two fleet alert windows are now configurable in Salis Settings._

- Workshop Overstay Days (default 14) — how long a vehicle may sit in the workshop before a Maintenance Overdue alert.
- License Alert Lead Days (default 30) — lead time for driver licence-expiry alerts.
- Both were already read by the alert jobs, but the fields were missing from the form, so they were stuck at their defaults; now they can be set.

## 1.54.17

_A Fleet dashboard reassignment fix from a security audit._

- Reassigning a driver on the Fleet board now fully succeeds or makes no change: if a concurrent reassignment wins the race, the second one is rejected cleanly instead of silently overwriting the vehicle's live driver and leaving an unsubmitted assignment behind.
- The reassign action now handles a blocked submit the same way the other Fleet actions already do.
- Found by an adversarial security audit of the /fleet feature (page, API and importer); the rest of the feature audited clean.

## 1.54.16

_More Fleet Operations: a workshop-overstay metric and in-page quick actions._

- New "Workshop Overstay" number card on the Fleet Operations workspace counts vehicles still in the workshop past the overstay cutoff — the same rule as the Maintenance Overdue alert, scoped to your permitted projects.
- The Operations Control page (Fleet Control) vehicle drawer now has quick actions to open a new Vehicle Stop, Vehicle Incident or Vehicle Assignment, prefilled with the selected vehicle.
- Both reuse existing logic and the native submittable forms — no duplicate write paths.

## 1.54.15

_The Fleet dashboard is rebuilt the idiomatic Frappe way — a Vue single-page app — while keeping the supervisor's exact design._

- The /fleet board now runs as a Vue app (the fleet_portal portal, like /driver and /masar), reading and writing the same live Salis DocTypes through the same permission-gated API; the look is unchanged.
- Removed the obsolete version/date line and the dead Save / Export / WhatsApp buttons (Apex is the datastore), and added loading, empty (clear-filters) and error (retry) states.
- Added a subtle entrance animation, a keyboard focus ring and a reduced-motion option; the board stays responsive on phones and tablets.
- A signed-in user without a fleet role now sees a friendly "fleet role required" page instead of a raw 403; guests are still redirected to login.

## 1.54.14

_Security hardening for the Fleet dashboard (skeptics-audit fixes)._

- Driver phone and external id (permlevel-1 fields) are now hidden on the Fleet dashboard and Dispatch Board from roles not granted them — Fleet Supervisor and Fleet Project Manager see driver names, not their contact details.
- Reassigning a driver from the Fleet dashboard now checks permission on the driver too, not only the vehicle, so a project-scoped supervisor cannot pair an out-of-scope driver to a vehicle.
- Reassignments now stamp the project on the assignment so its own scope rule applies.

## 1.54.13

_Fix the Fleet dashboard cards failing to render._

- The /fleet board threw a script error ("cannot read properties of undefined") and showed no vehicle cards.
- Cause: the dashboard API returned a vehicle's current driver as a partial record, missing the project and date fields the card reads.
- The API now returns the current driver in the same full shape as a custody-history entry, so every card and detail panel renders.

## 1.54.12

_A new /fleet web dashboard — the supervisor's own fleet board, now live._

- /fleet serves the fleet supervisor's exact dashboard design, with every vehicle, driver and custody record read live from the Salis DocTypes instead of a static file.
- Its actions update the real records: reassigning a driver, stopping a vehicle, sending it to or returning it from the workshop, recovering it, and reporting a theft.
- It opens for logged-in fleet roles only; the obsolete Save and Export buttons are gone because the data now lives in Apex.

## 1.54.11

_More Fleet Operations surfaces and the last schema fields._

- Two new charts on the Fleet Operations workspace: an Operating Days trend and a Vehicle Activations trend, both by month.
- Vehicle Stop now records the workshop-exit details (return date, released on and by, estimated cost) so a maintenance stop can be closed out.
- Salis Settings gains reference fuel prices (Petrol 91, Petrol 95, Diesel) for fuel budgeting.

## 1.54.8

- Fleet Control (opened from the Fleet Operations workspace) lists every vehicle as a status-coloured card or a table, with filters for status, rental office and project and a plate/category search.

## 1.54.7

_A new Fleet Operations workspace brings the day-to-day fleet control surface together in one place._

- A public Fleet Operations workspace groups the live fleet metrics, the incident queue, custody actions and office-billing links for fleet supervisors and managers.
- New metrics surface open vehicle incidents and open theft reports at a glance, alongside the existing active, stopped, under-maintenance and active-driver counts.
- An Incidents by Type chart and an open-incident quick list make the current incident load visible directly from the workspace.

## 1.54.6

_Foundations for the new Fleet Operations capability: a vehicle incident record and supporting fields, reusing the existing fleet model._

- A new Vehicle Incident record captures accident and theft events against a vehicle (location, police report number, fault and evidence); submitting a theft takes the vehicle out of service and clears its driver, and cancelling restores them.
- A damage write-off can now be linked back to the incident it was escalated from, and carries the damaged parts and who reported them.
- Vehicles gain an optional planned fuel grade and daily fuel budget, and drivers carry a unique external fleet identifier used as the data-import key.

## 1.54.5

_Closes a finance-approval bypass in payment routing: a real payment can only be created from a request the finance team actually approved._

- A payment request now counts as finance-approved only from the server-recorded approver stamped during the finance-approval step, never from its editable status field, so setting a request's status to "Paid" or "Approved by Finance" outside the approval step can no longer trigger a real payment.
- That approver record is now owned by the server: only the finance-approval step can write it (after the finance-role and segregation-of-duties checks), so it can no longer be set or forged when a request is created or edited.
- The approver is recorded on entry to every finance-gated state (both "Approved by Finance" and "Paid"), so an approved or paid request always carries the proof that finance cleared it.

## 1.54.4

_Critical security and accommodation-capacity fixes: serialize routed-payment creation, gate it at the chokepoint, and derive building bed capacity from actual physical beds._

- Routed-payment creation is now serialized with a row-lock, so two concurrent requests can no longer create a duplicate payment or a double ledger post.
- The routed-payment permission gate moved to the chokepoint, so every caller -- including any future direct caller -- is authorized before the payment is built.
- A building's Total Bed Capacity now derives from its actual physical beds (excluding out-of-service and virtual over-capacity beds), so occupancy, cost-per-capacity and over-capacity figures cannot drift; the field is read-only.

## 1.54.3

_Worker portal (Masar) fixes: a correct landing tab and active-state highlight, real session and permission error handling, and Arabic-localized status values._

- The portal's bottom Accommodation tab is now labeled and highlighted correctly; the landing tab no longer stays lit on every screen.
- A revoked, expired, or rate-limited session now shows a clear error with a retry, instead of a misleading empty 'nothing here' state.
- Status, request-type, category, and priority values now display in Arabic in the Arabic interface.
- Added the Arabic web font, international WhatsApp links, a larger language-toggle tap target, and minor navigation polish.

_Security and accommodation fixes: routed-payment permission recheck plus new security CI gates, the Site as the single building-address source, derived building capacity, a Habitat Hub onboarding step, and a model cleanup._

- Accommodation Site is now the single source of truth for a building's address; the building shows it read-only, ending duplicate address entry.
- Building total capacity now derives from its rooms' bed capacity.
- The Habitat Hub landing workspace now carries the Accommodation Go-Live onboarding.
- Removed an unused depreciation-policy field and its stale dashboard back-link.

## 1.54.0

_Six business features: financial integration, salary-deduction layer, cost-field privacy, safety auto-tickets, rider guard, and model cleanup._

- Financial integration is now live: a finance-approved payment request becomes a real payment document (Frappe's native Payment Request by default), and General Ledger posting is gated by the enable-GL-posting switch.
- New policy-driven salary-deduction layer (skeleton): a deduction policy plus per-type rules (damage, rent, fuel, custody) and an employee consent record, with Saudi-labour-law caps and NO deduction until explicitly activated.
- Sensitive cost figures are now hidden from non-finance roles via field-level permissions, scoped to finance and the Accommodation Manager role.
- Safety inspection findings now auto-generate Maintenance Requests (one per actionable finding, idempotent).
- A rider on leave or marked inactive can no longer be issued a vehicle or fuel; instead a clearance task is opened for the movement supervisor to recover the vehicle and custody.
- Removed two unused dead fields as part of the model-integrity cleanup.
