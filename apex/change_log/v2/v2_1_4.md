# Apex 2.1.4

Permission decisions now explain themselves in the code, and the gates that guard the repository are themselves guarded

- The reason two finance and audit roles may read every worker's custody holdings now sits beside the permission rows, with tests that fail if a narrower grant becomes possible
- The worker credential field states plainly that its protection level hides the stored token from the desk, not from an authorised issuer
- The gate fixture suites that prove the comment and commit-message checks now run from a lane that executes, instead of only when someone typed the command
- Fleet employee endpoints call the vehicle helper directly instead of through a passthrough kept only for tests
