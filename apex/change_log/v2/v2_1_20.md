# Apex 2.1.20

Transport request authorization now says who may approve, fleet roles can pick a project again, uploaded photos must really be images, and telecom billing works for a period that has already closed.

- A transport request could never be authorized by the person who raised it, but the form did not say so and let you edit Requested By as if that would help. The rule is now stated on the field, the field is fixed to whoever raised the request, and authorization goes to another supervisor or to the fleet manager.
- Fleet supervisors, fleet managers, fleet project managers and the finance manager can select a Project on a transport request. Before, the picker refused them outright.
- A file that is not really an image is now refused when you attach a shift photo or a worker request photo. Before, a renamed text file was accepted and stored as a picture.
- A purchase request can now be raised for a telecom billing period that has already ended, which is the normal case. Before, it was always refused.
- Carried over from the previous release, which shipped these without a note: the fleet board filter panel opens on a tablet again, the housing count bar no longer sits on top of the first item's plus and minus buttons, and the counted-versus-expected difference updates as you type instead of after saving.
- Nothing changes on screen from the rest of this batch: the operator documentation was restructured, and the permission reference is now generated from what the app actually ships.
