# Apex 2.1.9

The integration guide stops asking browsers to hold a secret, and the whole codebase settles on one indentation style

- Browser and mobile integrations are now documented with the authorization-code flow and a per-login proof instead of an API secret, and the remaining key-and-secret example runs on a server
- Every Python file in the application is indented with spaces, matching the editor configuration, with no change to what any line of code does
- The rename step added earlier no longer reports a failure on a site that has not applied it yet
