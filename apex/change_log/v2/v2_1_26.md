# Apex 2.1.26

Safety task instructions no longer name a client or a client policy.

- The seeded safety tasks explain why each one exists. Twenty-one of them gave that reason as a named client's audit finding or that client's internal policy, and every site installed those sentences into the task instructions an operator reads. Each now states the same requirement without naming anyone.
- Nothing else changes on screen. The permission reference page and the script that generated it were a maintainer's view of the app's own permission data and have left the repository, along with two upgrade steps that had been doing nothing since the dashboards moved to standard JSON.
