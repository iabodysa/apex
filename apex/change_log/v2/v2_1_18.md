# Apex 2.1.18

The personal worker link the demo seeder prints now opens the portal instead of failing.

- The demo seeder was printing the stored fingerprint of a worker's personal link instead of the link itself, so the address it handed the operator could never open the worker portal.
- It now asks for the link the same way the desk button does when a supervisor shares one, so there is a single definition of that address instead of two that can drift apart.
- A test now holds that behaviour in place: it fails if the recipe ever goes back to reading the stored field or spelling the address a second time.
