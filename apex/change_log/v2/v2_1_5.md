# Apex 2.1.5

Alerts no longer point at records their audience cannot open, and an incompatible framework argument is caught in seconds instead of mid-suite

- A safety reminder that linked a building its audience cannot read now names the building in the message instead, and the remediation-plan alert reaches the role that can actually open and close the plan
- Every system alert is checked against the permissions of the role it reaches, so an alert pointing at an unreadable record fails the build
- Application calls into the framework are checked against the installed signature, so an argument the framework has dropped is named with its file and line
- The checkout clearance print format carries the current name in the print dropdown, renamed on existing sites without touching the printed output
